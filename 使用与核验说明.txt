Reelay V9.14.4 · 单页定价计算器

使用
直接用浏览器打开 reelay_pricing_workbench_v9.html。已打开页面需刷新。template.html 是构建源码，不包含运行脚本，不能直接作为计算器使用。
页面离线运行，不调用模型、不执行充值。草稿保存在浏览器；重要方案导出 JSON。

页面与计算边界
默认页面为一个连续计算器，没有模型估价与平台定价两个Tab。
页面按生成估算与平台定价分成左右两栏，桌面宽度约3.5:6.5，左栏最小320px，顶端对齐；900px及以下依次纵向显示。
左栏“生成任务”：模型、视频输入、分辨率、画面比例、输出时长，下接Token用量与“估算视频费用”。该价格就是刊例费用 P；单价表通过“用量说明”查看。比例按钮下方单独一行显示像素尺寸与24 fps，不显示预览框；像素尺寸随当前模型、分辨率和比例更新。
右栏“平台定价”：上方直接并列实际支付、到账总积分、采购折扣、客户折扣四个字段，省去充值条件与模型折扣分组标题；字段标题采用原分组标题的12px、600字重与次正文颜色，随后是成本定价倍率。“本次任务”拆为右栏下方独立面板；桌面使用同一网格自动撑齐，底边与左侧生成任务对齐，不固定高度。实际支付与到账总积分共用；模型采购折扣、定价目标、倍率、精度独立保存。模型定价标题下，右侧输入框上方使用紧凑下拉切换客户折扣与毛利率；下拉兼任可见字段标题，与左侧采购折扣标签对齐，不重复显示名称。成本定价倍率数值是可点击的编辑入口，编辑时原位显示输入、保存和取消，Enter保存、Esc取消；打开或输入草稿均不改动定价，保存有效新值后才采用手动倍率。未改动当前有效自动倍率时保存不转成手动、不截断内部精度。自动输入原本无效时可通过确认备用倍率恢复有效手动规则。手动时上方显示当前倍率推导的折扣或毛利率，原目标仍保留；修改目标字段、快捷值或下拉会恢复自动计算，数值旁也提供恢复自动计算入口。切模型丢弃未确认编辑。自动倍率的精度入口为标题末尾的Bootstrap Icons调节图标；点击在按钮旁打开横向浮层，标签与选项同排；窄屏分成两行，仍保持标签在左、选项在右。仅含最大小数位（含不限）与舍入方式，合法修改立即应用。无效的零倍率设置只提示，不改动有效设置；Esc、外点、焦点离开或切换模型可关闭浮层。倍率右侧仅显示互补结果：客户折扣模式显示模型毛利率，毛利率模式显示折合客户折扣。倍率数字使用固定字号，不随数值长度变化；编辑时取消、保存在输入控件内部右侧，与文本区域分开，不遮挡输入；自动倍率以最多12位小数作为编辑草稿，未改动保存仍保留内部精度，手动输入保留原值。采购与客户折扣有简短快捷值。
右栏按容器宽度适配：699px以下收紧间距，559px以下充值与模型定价纵向排列，299px以下再缩小字段间距。外层保留3.5:6.5和900px以下上下布局。本次任务通过官方刊例成本、预计采购成本、立画实际成本三个tab选择本次计价依据，金额始终可见，省去独立的计算依据下拉。默认选预计采购成本。刊例模式以C=P计价，预计采购模式以C=P×采购折扣÷10计价，立画模式沿用实际输入或记录的成本口径；切换只影响本次任务，保持当前模型倍率、采购折扣与充值方案不变。下方统一展示取整前积分、核算扣分、折合金额，再展示目标售价、与目标差额、本次客户折扣，浅色摘要条只显示单次任务毛利，毛利率放在计算明细。折扣目标基于对应P，毛利目标按选中C计算；固定倍率时显示取整前金额和取整差额。缺少有效实际成本时，全部相关结果为“—”。
成本tab使用单选语义和键盘左右/Home/End操作，缺成本的立画tab仍可选。页签直接连接下方结果面板：未选项为浅灰底，选中项白底与面板相接、顶部有细蓝线。三个未选标签的标题、金额和留白同属一个按钮，整块可点击。仅选中立画页签后，数字位置显示独立输入框，保持在tablist和button之外；多条同规格记录的选择器放在实际成本内容区，不撑高三个标签。生成参数改变、成本清空或填错时保留已选来源，不借用其他任务实测或理论结果。重置、导入和重新打开默认使用预计采购。窄屏成本tab保持三列，长数字可横向查看。计算明细跟随当前来源；刊例模式直接采用刊例金额、不应用采购折扣，并沿用当前倍率。
用量说明、模型定价总览、计算明细均为蓝色文字链接。
“计算明细”面板与用量说明共用1280px最大宽度和固定视口适配高度，互相跳转不改变外框大小。计算过程分为计价成本、积分扣除、折合金额三段；下方倍率、单次任务毛利、差额核对、金额校验以两列默认展开，目标金额收在差额核对中，原始来源与历史实扣置于底部。900px以下计算阶段纵向排列、内部两列；520px以下内部一列。长算式允许换行，面板内容超高时内部滚动。用量推导通过“用量明细”查看。
下方仅保留“折扣测算”，固定展开，不保留折叠按钮；参数摘要居右，以14px字重550显示模型、分辨率、比例、输出时长与视频输入；左侧用一句话说明随上方设置更新并按各档客户折扣计算倍率，桌面同排，窄屏按需换行且参数仍右对齐；已移除规格对比、充值对比及任务清单入口。实测对账从顶部进入。模型定价总览放在平台定价标题右侧，以当前共用充值条件比较三个模型的采购、定价依据、采用倍率与取整前折扣/毛利率；点击模型名切换到对应模型。
旧V9.4草稿若停留在platform页，会自动进入合并后的页面，保留定价、模型和历史数据。

模型估价不依赖平台输入。充值或折扣无效时，左侧仍能计算、查看依据并导出摘要；模型定价规则与共用充值条件分别保留有效设置。无效模型定价草稿不覆盖该模型上次有效规则，切换离开时提示；充值输入未完成时，新编辑的有效模型规则仍可保存。指定倍率不依赖隐藏的目标值，不计算参考目标金额或差额。无效生成参数不会显示上一组报价。

生成参数
模型置于参数区最前；随后为视频输入、分辨率、画面比例和输出时长。
比例顺序固定为21:9、16:9、4:3、1:1、3:4、9:16。
视频输入关闭时为平分整行的“无视频输入 / 有视频输入”两块。选中有视频输入后，选择区以220ms动画向左收为约30%，标签简化为“无 / 有”，右侧展开总时长、细滑条和小秒数框；选无时逆向收回；按钮保留同一组文字，“视频输入”后缀的宽度与透明度随格块同步过渡，不在动画结束时替换文字，避免居中位置跳变。选择区最小96px，整行始终38px高；参数区不足300px时，右侧采用总时长在滑条上方、秒数框纵跨两行，保留轨道长度。只有两个明确按钮可以切换，标题、外框和时长区域不触发切换；按钮始终保留完整无障碍名称和选择状态。关闭立即禁用时长控件并移出键盘及辅助技术访问，动画完成后隐藏；快速重开取消旧收尾，减少动画偏好下立即到终态。切换时不推动下方参数或用量，不改变已有草稿的任务状态。输出时长用主滑条，时长数值统一为15px。输入小数秒向上取整是本工具的交互策略，实测记录的小数时长保持原样。
2.5：480p/720p/1080p，输出4–30秒，视频输入总时长2–30秒。
2.0：480p/720p/1080p/4K，输出4–15秒，视频输入总时长2–15秒。
Fast：480p/720p，输出4–15秒，视频输入总时长2–15秒。
切换模型时保留兼容参数；超出支持范围的参数调整到可用范围，并提示具体改动。
快捷选项默认收起，底部入口同时作为展开与收起的把手。内容与入口边缘连接，展开顶部按Token用量块的实际位置对齐，随布局与窗口尺寸更新，裁切壳内的内容以220ms滑动展开或缩回，不改变生成面板高度；上方空间不足时连接入口向下展开。两行分别为无视频/有视频，两列为最低/最高用量，两行在对齐后的抽屉内均匀分配留白，按当前模型全部支持规格求极值。只保留分辨率、比例及输出/输入时长，不重复模型、标题或关闭按钮；窄栏中时长可换行。选择后自动收起并将焦点返回入口，也支持再次点击入口、Escape、外点及焦点离开收起。收起即禁用交互，动画结束后隐藏；快速重开取消旧关闭任务，减少动态效果偏好下立即切换。Token用量块可见时，抽屉高度由其顶部与入口之间的距离决定；该块已滚出视口或暂不可见时，按可用空间调整方向并限制为240px以内，必要时只在内容内部滚动。

估价呈现
有视频输入时，“估算 Token 用量”与“最低 Token 用量”并列，每格上方标题与采用标签同行，下方显示数值。常规用量行固定84px高；用量区宽度不超过340px时，两格统一100px高以容纳必要的标题换行，无/有视频切换仍保持相同高度。数字保持单行并按可用宽度在14–20px间调整，特别长的人工小数可横向滚动查看；不以省略号或万/百万替代数字。采用的一项通过底色和“采用”标签区分，两项数值使用相同颜色和字重；相等时采用估算项。两项不相加，不重复列第三个用量。下方“估算视频费用”固定采用名称在左、金额在右的横向排列；金额后紧跟“元/个”，字重稍强。数字靠右是单项结果的默认规则；仅有视频时的两项Token保留名称在上、数值在下的并列形式，以容纳完整数字。
无视频输入时“估算 Token 用量”跨两列，名称在左、数字在右，与下方费用采用同一阅读方向；隐藏最低用量，与并列状态保持同样高度；只保留中性卡片底色，不显示选中强调色或“采用”标签；模型估价摘要采用相同命名与显示规则。最低用量被采用时不重复显示提示句。人工覆盖明确标记，来源缺失时暂停完整视频价格和平台定价。
“用量说明”是最大1280px宽的居中浮层，随窗口收缩，长内容在浮层内滚动。左侧保留132px标题目录，可跳转本次计算、模型刊例价、分辨率映射与相关资料四章；目录跟随阅读位置高亮。窗口小于1100px时改为顶部横向目录。更新参数时保留纵向阅读位置、目录及表格横向位置；重新打开回到本次计算。顶部“本次计算”按估算Token、计费 Token 用量、估算视频费用三步整合规则说明、公式与当前数据代入。估算公式明确使用输出宽、高与帧率；有视频时与查表最低用量取较大值，查表维度紧随本次比较，无视频时直接采用估算用量。人工门槛及其来源备注集中在计费 Token 用量步骤，最低用量缺失时不展示完整费用。三步下方统一说明Token用量为估算值、以API的usage.completion_tokens为准；有视频时明确最低Token也是估算值。说明保留保存计算器字段描述的必要含义，不再另设两项Token说明章节或重复公式。Token保留精确值，说明中的费用显示六位小数，显示舍入时使用约等号。左侧摘要默认两位小数，可切换六位；该显示偏好不改变计价。随后展示2.5、2.0、2.0 Fast的刊例价表（元/百万Token）与分辨率映射，费率使用经过来源校验的模型目录。模型价格、分辨率说明、计算器和最低用量表的六个链接统一放在浮层内容底部，按文档、计算器、最低用量表三组排列；2.0/Fast与2.5各自指向对应的官方表。画面比例与像素分辨率表列出三模型的54项映射，默认每格只显示宽×高，标题旁的“显示总像素”开关可展开或收起精确总像素；显示偏好仅在当前页面会话保留，不改动方案或计价。统一样式，不使用最大值颜色或标签。尺寸取自核验后的模型目录，保留2.5与2.0的480p差异；窄屏可横向滚动表格。来源核验过程不在此面板展示。
左侧视频费用估算 P 是按刊例价计算的模型费用，右侧采购成本 C 为 P 乘当前模型的采购折扣，两者均为估算值。
固定规格是预计输出规格；编辑、延长等任务需按实际确定的输出规格重新核算。该工具不是通用 API 请求参数生成器。

平台定价
计算明细与用量说明共用最大1280px居中面板，按成本、积分、金额顺序展示公式和数据。理论、临时录入、历史实测使用一致的两列六项流程；实测的倍率与模型毛利并排，目标差额与历史实扣并排，来源和API核对另列。公式区默认展开；有多条同规格记录时才显示切换选择器。Token推导通过“用量明细”进入用量说明并可返回。模型总览最大1000px，表格单独横向滚动。精度设置不再重复定价模式选择。
采购折扣与客户折扣独立。10折即无折扣；客户快捷档为7.35、7.8、8、无折扣。
根据当前采购情况，仅 Seedance 2.0 已有折扣供应商，保留其现有采购折扣；Seedance 2.5 与 2.0 Fast 默认10折。其它模型可调整折扣作未来方案测算，页面与导出明确标为模拟采购，不表示已接入供应商。
每个模型保存完整定价规则，切换模型不会互相覆盖。新建方案中2.0沿用7.35折采购与客户折扣；2.5、Fast默认无采购折扣（q=1）、固定成本定价倍率1.65，客户折扣与模型毛利由当前充值条件折算。旧草稿缺少modelPricing时，将原共用定价规则按各模型既有采购折扣展开，保持迁移前的扣分结果。已有规范化规则表的导入以规则表为准，旧镜像字段不覆盖它。浏览器旧草稿中，只有与过去占位默认完全一致的2.5/Fast规则自动更新至1.65；已自定义规则、2.0及旧版共用方案保持不变。pricingDefaultsRevision记录此次默认更新，显式导入的方案保持原值并标记已处理，刷新后也不会改用新默认。跨模型任务、实测复算与明细使用各自模型的规则；原始P/C/N不改写。
到账总积分仅填写总额，包含赠送部分；不再提供附赠积分切换。旧giftMode草稿保留已经保存的到账总额，归一为总积分输入，改变支付金额不会隐式改变到账积分。两个字段下方分别显示每元积分和每积分金额。
定价方式下拉选择客户折扣或目标毛利率；直接编辑成本定价倍率则改用手动倍率。精度设置仅处理自动倍率，包含是否限制小数位、位数、四舍五入/截断，并预览本次扣分变化；手动输入保留其输入精度。切换经指定倍率后返回自动目标时保留原精度设置。任何造成采用倍率为0的草稿都不会写入模型规则。
100元到账1538积分，采购10折、客户10折时，自动倍率为1.538。2.5/Fast默认固定倍率1.65，对应取整前客户折扣10.7282折、模型毛利率6.7879%；这与客户无折扣不同。充值金额或积分变化时固定倍率保持1.65，折合金额、客户折扣与毛利随之更新；主动编辑客户折扣或毛利率会改用自动倍率。固定倍率不应用自动倍率的小数位限制。
本次任务按完整规格匹配实测：模型、分辨率、比例、输出时长、视频输入及输入总时长全部相同才接入；只有多条同规格记录时，立画实际成本输入下方显示紧凑选择器；无记录或仅一条记录时不占位。来源和历史实扣不再常驻主面板，查看、编辑、保存临时成本及恢复原记录值统一从计算明细进入。理论行与实测复算行都采用当前模型规则。历史实扣另列，并且不会使用当前充值条件伪造历史金额。缺少所需成本保持空白，零采购成本仍是有效记录。输入无效时清空相关结果，规则表现不受无效任务影响。
折扣测算使用当前生成参数、采购折扣、充值方案和自动倍率精度，对各档客户折扣计算；点击折扣可采用对应方案。固定倍率与各折扣场景分别计算，固定倍率下不高亮某个折扣档位。折扣测算不提供导出。旧草稿视图自动回到折扣测算；旧任务及充值对比数据保留在导入/导出数据中，不再提供编辑入口。

精确计算
基础用量 B=(输出秒数+输入秒数)×宽×高×24/1024。
有视频时查询对应模型最低用量L，采用max(B,L)；无视频时采用B。
P=采用用量×单价/1,000,000；C=P×采购比例q。
每元积分S=到账积分/实付，积分现金价值U=1/S。
折扣目标d：M=d×S/(q×10)。毛利目标g：M=S/[10×(1−g)]。
取整前积分I=C×M×10；每次扣分N=ceil(I)；折合金额=N×U。
模型毛利=折合金额−C，未扣税费、支付、存储、运维或失败重试成本。
内部采用精确有理数，显示舍入不参与计算。Token不按表格的整数显示提前取整。
API usage.completion_tokens 已含最低用量；不再次补门槛，不与total_tokens相加。

开发
本项目已独立Git管理，未配置远程Git仓库。公网部署使用Vercel项目reelay-pricing-v9（Heo's projects）；vercel.json指定构建命令和dist输出目录，仅发布构建后的单页。
engine.js：精确计算与平台财务；data.js：标准2.0规则兼容层。 pricing-profiles.js：模型规则规范化、独立保存与兼容迁移。
models.js：三模型目录和独立估价；app.js：分层交互；template.html：页面。
source-rules.cjs与models-source.cjs：原始来源验证与最低用量生成。
model-catalog-check.cjs：官方文档到模型目录的费率、尺寸、能力核对。
构建：npm run build。回归：npm test。来源检查：npm run rules:check。
输出：reelay_pricing_workbench_v9.html、dist/index.html。运行页面不需安装包。
源码归档：reelay_pricing_v9_source.zip。
部署：先运行npm test与npm run build，再执行vercel deploy --prod --scope heos-projects-560eccff。本地绑定与环境文件不进入Git或源码归档。公网与file页面使用不同的浏览器存储，已有方案可通过JSON导出/导入迁移。
浏览器file:访问受工具限制，交互通过JSDOM验证；未声称完成真实本地浏览器视觉验收。
不要运行早期遗留转换脚本upgrade_app.py，它不属于当前构建流程。

图标使用Bootstrap Icons 1.13.1字体版（MIT），来源与许可位于assets/bootstrap-icons，构建时嵌入独立HTML，离线可用。
录入实测：顶部显示任务摘要，规格编辑默认收起；新记录默认“立画实际成本（直接采用）”，实际成本必填，历史实扣可选，两项并排。另一方式为“折前成本（按采购折扣换算）”，折前成本必填，实际成本按当前折扣核算。直接录入方式下折前成本为折叠可选项，仅用于客户折扣与目标售价对照。切换方式保留未保存字段草稿；补充名称、日期、API用量、备注默认收起。名称空白时按最终任务自动命名。取消与保存固定在抽屉底部；校验失败展开对应字段并聚焦，零成本有效。已有记录保留原有录入方式和原始数据；旧的部分记录缺少C时仍可修改备注，不强迫补造成本。
新记录只可带入同规格、同记录上下文中的有效临时成本；P和历史N不自动推测。无效临时金额不会被旧的有效草稿替代。保存同规格临时成本且P留空时保留当前计算基准，不把理论P写入历史证据；主动录入P后转用已录入的折前成本核算。修改任务规格不继承原规格的临时成本上下文。编辑原记录后清除该记录的旧临时覆盖，以免新成本被遮住。

视觉：平台定价与本次任务统一标题间距和链接；倍率使用轻底色承载。任务三列成本弱化，扣分与金额突出，目标差额和毛利为辅助层，记录来源、历史实扣与记录操作集中在计算明细中。立画成本tab沿用原实测成本复算逻辑。

本次任务的三个成本tab始终可切换（任务或平台参数整体无效除外）。立画成本未选中时显示金额或—，整块可点击；选中后才在同一数字位置显示输入框，同规格多记录选择器仅在实际成本内容区出现。切换规格、记录、清空或输入无效金额时保留选中的成本来源；没有有效实际成本时全部相关结果显示—，并提示录入，不回退理论或旧记录。0成本有效，最多20位小数。有效录入和主动清空保存在本地及JSON方案，按任务规格与来源记录绑定；无效草稿优先覆盖当前显示与明细导出，但不持久化错误值。原记录可在明细中恢复。输入成本不再乘采购折扣；主面板只显示单次任务毛利，毛利率留在明细。
