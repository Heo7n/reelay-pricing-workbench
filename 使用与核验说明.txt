Reelay V9.6.0 · 单页定价计算器

使用
直接用浏览器打开 reelay_pricing_workbench_v9.html。已打开页面需刷新。
页面离线运行，不调用模型、不执行充值。草稿保存在浏览器；重要方案导出 JSON。

页面与计算边界
默认页面为一个连续计算器，没有模型估价与平台定价两个Tab。
页面按生成估算与平台定价分成左右两栏，桌面宽度约3.5:6.5，左栏最小320px，顶端对齐；900px及以下依次纵向显示。
左栏“生成任务”：模型、视频输入、分辨率、画面比例、输出时长，下接Token用量与“估算视频费用”。该价格就是刊例费用 P；单价表通过“用量说明”查看。比例按钮下方单独一行显示像素尺寸与24 fps，不显示预览框；像素尺寸随当前模型、分辨率和比例更新。
右栏“积分定价”：依次为充值条件与模型采购、定价规则、本次任务。充值金额与到账积分为共用条件；采购折扣、定价依据、目标或指定倍率、精度按模型独立保存。三种定价依据为客户折扣、目标毛利率、指定倍率。取整前客户折扣和模型毛利率常显，用于判断规则是否盈利；本次任务优先显示预计扣分、扣分折合金额，下方展示采购成本、模型毛利和毛利率。刊例费用不重复列在右侧。
右栏按自身容器宽度适配：充值与模型采购分组横排；719px以下收紧间距，459px以下采购移到充值下方，279px以下进一步纵排。外层保留3.5:6.5和900px以下上下布局。结果数字允许必要换行，避免挤出容器。
“对比测算”位于下方，默认收起，包含折扣测算、规格对比、充值对比、任务清单。实测对账从顶部进入。模型总览放在积分定价标题右侧，以当前共用充值条件比较三个模型的采购、定价依据、采用倍率与取整前折扣/毛利率；点击模型名切换到对应模型。
旧V9.4草稿若停留在platform页，会自动进入合并后的页面，保留定价、模型和历史数据。

模型估价不依赖平台输入。充值或折扣无效时，左侧仍能计算、查看依据并导出摘要；模型定价规则与共用充值条件分别保留有效设置。无效模型定价草稿不覆盖该模型上次有效规则，切换离开时提示；充值输入未完成时，新编辑的有效模型规则仍可保存。指定倍率不依赖隐藏的目标值，不计算参考目标金额或差额。无效生成参数不会显示上一组报价。

生成参数
模型置于参数区最前；随后为视频输入、分辨率、画面比例和输出时长。
比例顺序固定为21:9、16:9、4:3、1:1、3:4、9:16。
视频输入关闭时为平分整行的“无视频输入 / 有视频输入”两块。选中有视频输入后，选择区以220ms动画向左收为约30%，标签简化为“无 / 有”，右侧展开总时长、细滑条和小秒数框；选无时逆向收回；按钮保留同一组文字，“视频输入”后缀的宽度与透明度随格块同步过渡，不在动画结束时替换文字，避免居中位置跳变。选择区最小96px，整行始终38px高；参数区不足300px时，右侧采用总时长在滑条上方、秒数框纵跨两行，保留轨道长度。只有两个明确按钮可以切换，标题、外框和时长区域不触发切换；按钮始终保留完整无障碍名称和选择状态。关闭立即禁用时长控件并移出键盘及辅助技术访问，动画完成后隐藏；快速重开取消旧收尾，减少动画偏好下立即到终态。切换时不推动下方参数或用量，不改变已有草稿的任务状态。输出时长用主滑条，时长数值统一为15px。输入小数秒向上取整是本工具的交互策略，实测记录的小数时长保持原样。
2.5：480p/720p/1080p，输出4–30秒，视频输入总时长2–30秒。
2.0：480p/720p/1080p/4K，输出4–15秒，视频输入总时长2–15秒。
Fast：480p/720p，输出4–15秒，视频输入总时长2–15秒。
切换模型时保留兼容参数；超出支持范围的参数调整到可用范围，并提示具体改动。
快捷选项默认收起，底部入口同时作为展开与收起的把手。内容与入口边缘连接，展开顶部按Token用量块的实际位置对齐，随布局与窗口尺寸更新，裁切壳内的内容以220ms滑动展开或缩回，不改变生成面板高度；上方空间不足时连接入口向下展开。两行分别为无视频/有视频，两列为最低/最高用量，两行在对齐后的抽屉内均匀分配留白，按当前模型全部支持规格求极值。只保留分辨率、比例及输出/输入时长，不重复模型、标题或关闭按钮；窄栏中时长可换行。选择后自动收起并将焦点返回入口，也支持再次点击入口、Escape、外点及焦点离开收起。收起即禁用交互，动画结束后隐藏；快速重开取消旧关闭任务，减少动态效果偏好下立即切换。Token用量块可见时，抽屉高度由其顶部与入口之间的距离决定；该块已滚出视口或暂不可见时，按可用空间调整方向并限制为240px以内，必要时只在内容内部滚动。

估价呈现
有视频输入时，“估算 Token 用量”与“最低 Token 用量”并列，每格上方标题与采用标签同行，下方显示数值。常规用量行固定84px高；用量区宽度不超过340px时，两格统一100px高以容纳必要的标题换行，无/有视频切换仍保持相同高度。数字保持单行并按可用宽度在14–20px间调整，特别长的人工小数可横向滚动查看；不以省略号或万/百万替代数字。采用的一项通过底色和“采用”标签区分，两项数值使用相同颜色和字重；相等时采用估算项。两项不相加，不重复列第三个用量。下方“估算视频费用”固定采用名称在左、金额在右的横向排列；金额后紧跟“元/个”，字重稍强。数字靠右是单项结果的默认规则；仅有视频时的两项Token保留名称在上、数值在下的并列形式，以容纳完整数字。
无视频输入时“估算 Token 用量”跨两列，名称在左、数字在右，与下方费用采用同一阅读方向；隐藏最低用量，与并列状态保持同样高度；只保留中性卡片底色，不显示选中强调色或“采用”标签；模型估价摘要采用相同命名与显示规则。最低用量被采用时不重复显示提示句。人工覆盖明确标记，来源缺失时暂停完整视频价格和平台定价。
“用量说明”是最大1280px宽的居中浮层，随窗口收缩，长内容在浮层内滚动。左侧保留132px标题目录，可跳转本次计算、模型刊例价、分辨率映射与相关资料四章；目录跟随阅读位置高亮。窗口小于1100px时改为顶部横向目录。更新参数时保留纵向阅读位置、目录及表格横向位置；重新打开回到本次计算。顶部“本次计算”按估算Token、计费 Token 用量、估算视频费用三步整合规则说明、公式与当前数据代入。估算公式明确使用输出宽、高与帧率；有视频时与查表最低用量取较大值，查表维度紧随本次比较，无视频时直接采用估算用量。人工门槛及其来源备注集中在计费 Token 用量步骤，最低用量缺失时不展示完整费用。三步下方统一说明Token用量为估算值、以API的usage.completion_tokens为准；有视频时明确最低Token也是估算值。说明保留保存计算器字段描述的必要含义，不再另设两项Token说明章节或重复公式。Token保留精确值，说明中的费用显示六位小数，显示舍入时使用约等号。左侧摘要默认两位小数，可切换六位；该显示偏好不改变计价。随后展示2.5、2.0、2.0 Fast的刊例价表（元/百万Token）与分辨率映射，费率使用经过来源校验的模型目录。模型价格、分辨率说明、计算器和最低用量表的六个链接统一放在浮层内容底部，按文档、计算器、最低用量表三组排列；2.0/Fast与2.5各自指向对应的官方表。画面比例与像素分辨率表列出三模型的54项映射，默认每格只显示宽×高，标题旁的“显示总像素”开关可展开或收起精确总像素；显示偏好仅在当前页面会话保留，不改动方案或计价。统一样式，不使用最大值颜色或标签。尺寸取自核验后的模型目录，保留2.5与2.0的480p差异；窄屏可横向滚动表格。来源核验过程不在此面板展示。
左侧视频费用估算 P 是按刊例价计算的模型费用，右侧采购成本 C 为 P 乘当前模型的采购折扣，两者均为估算值。
固定规格是预计输出规格；编辑、延长等任务需按实际确定的输出规格重新核算。该工具不是通用 API 请求参数生成器。

平台定价
计算明细采用最大920px居中面板，按采购成本、定价倍率、预计扣分、金额与毛利四步展示公式和本次数据。Token推导通过“查看用量计算”进入原用量说明并可返回；金额校验内嵌收起。模型总览最大1000px，表格单独横向滚动。精度设置不再重复定价模式选择。
采购折扣与客户折扣独立。10折即无折扣；客户快捷档为7.35、7.8、8、无折扣。
根据当前采购情况，仅 Seedance 2.0 已有折扣供应商，保留其现有采购折扣；Seedance 2.5 与 2.0 Fast 默认10折。其它模型可调整折扣作未来方案测算，页面与导出明确标为模拟采购，不表示已接入供应商。
每个模型保存完整定价规则，切换模型不会互相覆盖。新建方案中2.0沿用7.35折采购与客户折扣；2.5、Fast默认10折采购与客户折扣。旧草稿缺少modelPricing时，将原共用定价规则按各模型既有采购折扣展开，保持迁移前的扣分结果。已有规范化规则表的导入以规则表为准，旧镜像字段不覆盖它。跨模型任务、实测复算与明细使用各自模型的规则；原始P/C/N不改写。
到账总积分可切换为附赠积分填写；附赠模式按实付金额×10加赠分求到账总量。
定价依据直接选择客户折扣、目标毛利率或指定倍率；前两者自动求倍率，指定倍率直接采用输入。精度设置仅处理自动倍率，包含是否限制小数位、位数、四舍五入/截断，并预览本次扣分变化；手动输入保留其输入精度。切换经指定倍率后返回自动目标时保留原精度设置。任何造成采用倍率为0的草稿都不会写入模型规则。
100元到账1538积分，采购10折、客户10折时，自动倍率为1.538；手动1.65是另一个有效定价方案。
主结果只显示预计扣分、扣分折合金额、采购成本、模型毛利和毛利率。规则毛利与本次任务毛利分别显示，避免小额任务取整掩盖规则亏损。规则亏损或客户价格高于刊例时给出条件提示。输入无效时清空相关结果；若只有任务参数无效，仍保留有效的规则表现。
对比测算默认收起。充值对比默认保持当前模型采用倍率，观察赠分影响；另可选择调整倍率保持目标，并遵守该模型精度设置。指定倍率没有隐含目标，不能用隐藏的目标重新定价。固定倍率取当前模型实时值，不沿用其它模型或旧时刻的冻结倍率。任务清单仅保存参数和数量，按各模型当前规则重新计算，表内显示采用倍率；每次取整后乘数量。

精确计算
基础用量 B=(输出秒数+输入秒数)×宽×高×24/1024。
有视频时查询对应模型最低用量L，采用max(B,L)；无视频时采用B。
P=采用用量×单价/1,000,000；C=P×采购比例q。
每元积分S=到账积分/实付，积分现金价值U=1/S。
折扣目标d：M=d×S/(q×10)。毛利目标g：M=S/[10×(1−g)]。
取整前积分I=C×M×10；每次扣分N=ceil(I)；折合金额=N×U。
模型毛利=折合金额−C，未扣税费、支付、存储、运维或失败重试成本。
内部采用精确有理数，显示舍入不参与计算。Token不按表格的整数显示提前取整。
API usage.completion_tokens 已含最低用量；不再次补门槛，不与total_tokens相加。

官方来源与验证
核验日期2026-10-20，固定日期快照，不会自动联网更新。
2.0最低规则来自其独立官方表：192个原始行，288个输出规格。
Fast官方计算器明确与2.0共享最低表，仅支持480p/720p，按独立37/22费率计价。
2.5从另一张官方表独立提取：339行，324唯一行，展开486规格；480p16:9为854×480，与2.0的864×496不同。
2.5额外15行是480p21:9输出16–30秒的同值重复，逐行核验且保留来源行号；冲突会拒绝构建。线上官方表单16秒样例最低栏出现两次271188，价格仍为11.39元；不把重复最低值相加。
标准2.0与2.5均解释保存的官方原式，核对来源身份、公式和显示值后生成查表数据，不手写替代门槛公式。
各模型费率、尺寸与范围分别核验。原始文档、表格复制数据、字段JSON、哈希、方法和线上证据见 evidence/README.md。

迁移与导出
沿用V9方案格式和本地草稿键；旧方案中没有model的任务与记录明确迁移为Seedance 2.0标准版。
成功恢复旧草稿时不显示版本迁移说明；导入成功只显示简短确认，失败或实际参数调整仍提供必要提示。
保留V7/V8/V9导入、原始实测、人工门槛及倍率设置。人工门槛按模型/规则版本/输出规格隔离，不跨模型复用。
模型估价摘要可独立导出；完整方案JSON包含平台、任务和实测，可重新导入。CSV分别导出方案对比与实际对账，并注明模型和规则版本。

开发
本项目已独立Git管理，无远程仓库、未发布。
engine.js：精确计算与平台财务；data.js：标准2.0规则兼容层。 pricing-profiles.js：模型规则规范化、独立保存与兼容迁移。
models.js：三模型目录和独立估价；app.js：分层交互；template.html：页面。
source-rules.cjs与models-source.cjs：原始来源验证与最低用量生成。
model-catalog-check.cjs：官方文档到模型目录的费率、尺寸、能力核对。
构建：npm run build。回归：npm test。来源检查：npm run rules:check。
输出：reelay_pricing_workbench_v9.html、dist/index.html。运行页面不需安装包。
源码归档：reelay_pricing_v9_source.zip。
浏览器file:访问受工具限制，交互通过JSDOM验证；未声称完成真实本地浏览器视觉验收。
