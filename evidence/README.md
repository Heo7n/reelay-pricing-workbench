# 最低用量规则的来源与复核

本目录保留 **Seedance 2.0 标准版**规则 `volc-seedance20-2026-10-20`，并在 `2026-10-20/models/` 中独立取证 **Seedance 2.5** 规则 `volc-seedance25-2026-10-20` 及三模型参数、费率。最低 Token 用量本身也是估算值；API 返回的 `usage.completion_tokens` 才是准确用量。

## Seedance 2.0 原始证据

- `2026-10-20/calculator-public.html`：匿名读取[官方计算器](https://bytedance.larkoffice.com/share/base/form/shrcnP1Bl0mqCP9OHCbjpe1oBkf)的原始公开 HTML。
- `calculator-fields.json`：从上述 HTML 的字面 JSON 中提取字段，含获取时间、来源 URL 和 HTML SHA-256。构建器会再次独立提取并比对，不执行网页脚本。
- `minimum-{480p,720p,1080p,4k}.clipboard.json`：当日刷新[官方 Seedance 2.0 最低用量表](https://bytedance.larkoffice.com/wiki/FXaYwxzJ5i5Zdik32ipcWzt7nxd?table=tblmNCuMjADrXtDf&view=vew2CR2JYM)后，在每个视图全选48条记录并正常复制，保留浏览器剪贴板的原始返回。公式来自 `text/bitable` 的 `header.property.formula`，字段 ID 为 `fld0p1bMiB`。
- `record-1080p-16x9-4s.ax.txt`：展开单条记录及隐藏字段的界面读数，显示输出4秒、输入3秒、帧率24。仅为补充上下文，不参与计算。
- `manifest.json`：源文件和生成文件哈希，以及规格、记录和求值次数。

表格左侧明确分开2.0和2.5。计算器最低值查表目标是 `tblmNCuMjADrXtDf`；`tblheIYDXXwYM43b` 是2.5表，不能替换。只保存当前页面内容，不读取内部接口或浏览器隐藏状态。

## Seedance 2.0 的计算实现

官方计算器先按分辨率、比例、输出时长查最低值，再将它与基础估算取较大值。无视频输入不使用最低值。运行时采用同一流程。

复制数据的数值已经按表格的 `formatter: "0"` 显示取整；不能把它作为精确计价输入。构建器使用受限表达式解释器执行原始公式，在官方计算器列出的输入时长选项内求最小值，再逐条核对显示整数。全部通过后生成精确小数查找表，保留每项的原始视图、行号和来源文件。

原式中确实存在 `ROUNDUP(输出时长*2/3,0)`。这里保留它作为可校验的源公式，运行时代码不再单独手写一个等价阈值式。当前192条源记录因横竖比例共用，覆盖288个规格；4032次求值是288规格×14档输入时长，并非4032次API实测。

例如720p、4:3、输出4秒：精确最低值为152152.875，表格显示152153。输入2秒时按28元/百万Token计算得到4.2602805元。Token显示取整与积分逐笔向上取整是不同步骤。

## Seedance 2.5 独立取证

以下文件均位于 `2026-10-20/models/`，核验日期为2026年10月20日：

- `seedance-2.5-calculator-public.html` 和 `seedance-2.5-calculator-fields.json`：独立捕获[官方 Seedance 2.5 计算器](https://bytedance.larkoffice.com/share/base/form/shrcnhVCMxKxcwW1QML5r9u8nvh)公开 HTML 及其字段。计算器表为 `tblybhvNR0ukb7qp`，最低值查询指向 `tblheIYDXXwYM43b`，最低用量字段为 `fld0p1bMiB`。HTML 哈希、完整字段清单、选项及基础用量、最低值查询、价格 `IF/MAX` 原式均在构建时校验。
- `minimum-{480p,720p,1080p}.clipboard.json`：分别从2.5最低用量表的三个视图正常全选复制得到的原始剪贴板数据，含记录、原始字段公式和显示格式。视图 ID 依次为 `vew2CR2JYM`、`vewVBehIlq`、`vewdDcyFjS`。这些数据独立于2.0表；计算器 HTML 的查询公式本身不包含表内记录。
- `model-pricing.md`、`create-video-generation-task-api.md`、`get-video-generation-task-api.md` 及 `documents-manifest.json`：官方定价、创建任务、查询任务文档的原文与获取时间、URL、HTTP 状态、SHA-256。`models-metadata.json` 是对应的研究摘录，不能代替原始证据。2.5的480p 16:9为854×480、9:16为480×854，与2.0不同；生成器直接解析创建任务文档的2.5像素列。
- `minimum-manifest.json`：2.5生成文件与原始证据哈希、记录数、规格数及重复行来源。输出文件为根目录的 `generated-model-minima.js`。

官方计算器明确说明：“输入包含视频时，存在最低 token 用量限制。如果估算 token 用量 ＜ 最低 token 用量，则按最低 token 用量计算视频价格。”同时说明：“最低 token 用量为估算值，实际以调用 API 后返回的 usage.completion_tokens 字段为准。”因此最低值是官方估算规则中的下限，不是 API 实际返回值，也不是固定价格承诺。

`models-source.cjs` 仅共享受限公式解释器，独立读取2.5的模型身份、输入2–30秒、输出4–30秒、三档分辨率、六种固定比例及24帧/秒选项。它执行2.5表中捕获的原式，对每条记录枚举29档输入时长，取得精确最低值，再与该行按零位小数显示的 Token 核对。339条记录共进行9831次求值；横竖比例展开后得到486个规格。测试另外比较486规格×29档输入，共14094个有视频配置的原式结果与“基础用量、最低值取较大值”的结果；这些是规则核验，均非 API 实测。

### 339条记录与15条重复的处理

480p视图有123条记录，720p、1080p各108条，共339条。480p中21:9、输出16–30秒的15条记录各出现两次；去重后是324条原表记录。生成器对重复行仍独立求值和核验显示值，只允许这一明确集合，且两行的规格、像素、显示值和精确值必须完全一致。每个规格只生成一个最低值，同时保留两个源行号；任何其他重复或冲突均报错。没有将重复值相加，也没有静默丢弃异常记录。

`calculator-480p-21x9-16s.ax.txt` 保存了同日官方2.5表单的线上读数：480p、21:9、输出16秒、输入2秒、单价42元/百万 Token，最低用量显示 `271188, 271188`，价格显示 **11.39元**。单份最低值271188对应精确费用11.389896元，四舍五入到两位小数为11.39元；若两份相加则为22.78元。因此，这个重复规格的实际表单价格与保留一份最低值的处理一致。

该快照的“估算 token 用量”栏仍显示切换前的160704，属于未同步读数，不作为当前基础用量或公式正确性的数值证据。上述线上样例仅核对重复最低值与最终价格的关系，不据此推断飞书 `VALUE(LISTCOMBINE(...))` 对任意列表的通用转换规则；一般计算语义仍以捕获的原式和逐项验证为依据。

Seedance 2.0 Fast 的最低值共用关系来自2.0官方计算器本身：模型选项包含标准版与Fast，最低值查询不筛模型，费率查询单独筛模型。因此仅在Fast支持的480p、720p范围内共用2.0最低表；2.5继续使用自己的独立来源。

## 更新与失败处理

1. 新建日期目录，从同一模型的当前官方计算器和表格重新取证。
2. 核对模型、表和字段身份、规格范围、费率及原式变更；更新规则版本和版本校验摘要。
3. `npm run rules:build` 生成2.0数据，`npm run rules:check` 校验；`node models-source.cjs` 生成2.5数据，`node models-source.cjs --check` 检查其源证据和生成结果是否一致。2.5来源专项测试为 `node --test models-source.test.cjs`。
4. `npm run build`、`npm test` 通过后提交源码、证据、生成表和独立HTML。

缺字段、缺行、未经核验的重复规格、错误模型、维度不符、原式变化、显示值不符、HTML与字段提取脱节、生成文件过期均报错。构建不会联网悄悄替换规则，也不会在失败后继续输出旧数据。

根目录 `official-table-evidence.json` 保留为10月19日的历史显示值回归样本，当前构建与运行的来源是本目录。输入视频时长整秒化属于工作台输入策略；实测参数保留原始小数。

## 模型目录与官方正文闭环

`model-catalog-check.cjs` 直接解析本日期保存的官方定价 Markdown 与创建任务 API 文档，不依赖人工整理的 models-metadata.json。构建时核对运行时目录的三个模型、18个费率、54个像素映射，以及分辨率、整数输出时长、输入视频总时长和24 fps。原文与下载回执的URL、HTTP状态和固定版本哈希同时校验。改变文档、回执或运行时目录后，必须显式复核版本，不能静默产生新价格。运行 `node model-catalog-check.cjs --check`。
